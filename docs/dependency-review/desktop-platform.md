# Desktop platform and toolchain dependency review

Reviewed 2026-10-02 06:00 UTC (2026-10-01 in the workspace timezone). “Before” records the committed resolved lock version unless explicitly labeled as a manifest or script pin. “Selected” records the current integrated version or retained pin; newer candidates are listed separately. Final validation is tracked in the main review. Normal updates must be at least 72 hours old. No new age exception is needed here.

## Scope and evidence

Owned inventory: the Electron runtime, packaging/updating/rebuild tools and two electron-toolkit packages; Parcel watcher, node-pty, Windows process tree and universal ripgrep; sherpa-onnx and all five native packages; all ten xterm packages; TypeScript and its compiler-API alias, Vite alias, React Vite plugin, esbuild, Vitest, Playwright and Stably; Oxlint/plugins/type-aware engine, Oxfmt, React Doctor plugin/CLI, anti-slop, shadcn lint, Husky, lint-staged, i18next-cli, Happy DOM, three Testing Library packages, Node types, react-refresh, pngjs, pnpm and script-pinned Knip; Windows registry node-addon-api; Windows launcher winresource; mobile Fastlane. Koffi, keytar and better-sqlite3 are absent from direct manifests. The auxiliary appendix covers the server Node pin and every external GitHub Action family.

Version/date/peer evidence comes from each package’s primary npm registry endpoint linked in the matrices, RubyGems for Fastlane and crates.io for winresource. Registry metadata was captured before edits; all relevant dist-tags were inspected, including maintained `v26` releases that npm `latest` does not expose. Changelogs, release notes, security advisories and targeted upstream issue searches inform the decisions below. An absence of a discovered issue is not proof of absence of regressions.

Repository constraints read: [Linux native floor](../reference/linux-glibc-compatibility.md), [installation policy](../reference/pnpm-install-policy.md), [xterm patch regeneration](../reference/xterm-patch-regeneration.md), `config/patches/xterm-upstream.json`, native patches, watcher ignore handling, speech worker/model cache handling and mobile release lanes. Linux startup binaries retain glibc 2.31 / GLIBCXX 3.4.28; the existing lazy speech libstdc++ exception does not waive its glibc floor. Ordinary installs are host-only; cross-architecture packaging requires `pnpm install:release`.

Orca already explicitly sets renderer ES2020 and minifies with Oxc, so the default target/minifier switch is not itself a blocker. Concrete blockers are stable electron-vite 5’s peer range and the maturation of its beta 6 replacements. [Issue 894](https://github.com/alex8088/electron-vite/issues/894) describes native bundling/runtime failures despite successful compilation; Orca’s explicit native externals reduce that risk. [Issue 906](https://github.com/alex8088/electron-vite/issues/906) demonstrated ESM shim corruption into an empty main entry. The [beta changelog](https://github.com/alex8088/electron-vite/blob/v6.0.0-beta.5/CHANGELOG.md) fixes that in beta.4 (Sep 28), and beta.5 adds signal handling (Sep 29, under 72 hours). This review retains the proven alias rather than adopting an unaged beta to satisfy Vite 8. A later trial should update electron-vite/Vite/plugin-react together, validate main/preload/isolated worker entry graphs, native externalization, hidden renderer launch, projected web and mobile bundles, and dev termination; do not suppress peer ranges to force migration.
